# Building on Windows (WSL 2 + Docker)

Local firmware builds on this Windows machine. They use the same container image and
`build.sh` as the Linux/podman flow in `AGENTS.md`, run inside WSL 2. Verified on
`toucan2_zmk4_bt60` @ `59085c8` and `toucan2_zmk4_tofu65` @ `ee7727a`.

## Prerequisites

- WSL 2 distro `Ubuntu` (24.04), user `mbarrben`.
- Docker Engine inside WSL, running as a systemd service (`systemctl is-active docker`).
  The user must be in group `docker`. Podman is not installed, and `build.sh` falls back
  to docker on its own (override with `CONTAINER_ENGINE=...`).
- If `docker info` fails: `sudo systemctl start docker`.
- Image `docker.io/zmkfirmware/zmk-build-arm:4.1-branch`, already pulled.
- Workspace `~/.cache/zmk-ws-main` holds the zmk, zephyr and module clones, reused by
  every build. The container runs as root, so `build/` in there is root-owned. That's fine.

## Why a WSL-side mirror clone

Don't build from `/mnt/c/Users/miguel/projects/zmk-keyboard-toucan`:

- Global `core.autocrlf=true` (scoop git) gives the Windows checkout CRLF files
  (`git ls-files --eol` → `w/crlf`). Bash then dies on `set -euo pipefail\r`.
- Bind-mounting `/mnt/c` into the container is slow.

Build from the LF mirror `~/zmk-toucan-bt60` (ext4, `core.autocrlf=false`, `origin` = the
Windows repo) instead. **It only sees committed changes**, so commit in the Windows repo
first. One-time creation, if the mirror is missing:

```bash
wsl -- bash -lc 'git clone -c core.autocrlf=false /mnt/c/Users/miguel/projects/zmk-keyboard-toucan ~/zmk-toucan-bt60'
```

## Committing from the Windows checkout

Commit with plain `git commit -- <paths>`; git's autocrlf filter keeps the stored blobs LF.
Any tool that writes raw worktree bytes into the index would commit CRLF and break
`build.sh` in the mirror. Check with `git ls-files --eol <file>`; it must show `i/lf`.

## Sync + build

From a Windows shell:

```bash
wsl -- bash -lc 'cd ~/zmk-toucan-bt60 && git fetch -q origin && git checkout -q -B toucan2_zmk4_tofu65 origin/toucan2_zmk4_tofu65'
wsl -- bash -lc 'cd ~/zmk-toucan-bt60 && ./build.sh'
```

- Targets: `./build.sh [right left dongle reset tofu65 tofu65_reset] [--update]` (`bt60 bt60_reset` on `toucan2_zmk4_bt60`). The default
  is all of them. `dongle` builds all four prospector layouts (classic, radii, field, operator).
- Pass `--update` only after changing `config/west.yml`, or if modules are missing or
  fetches stall. It sets `http.version HTTP/1.1` inside the container.
- A full build is 9 pristine west builds and took about 1.5 min.
- Success means it prints the 9 `firmware/*.uf2` paths at the end. `set -e` stops the
  script before the copy step if any build fails. The log is the container's stdout.

**`$` trap:** `wsl -- …` re-parses its arguments through the distro's default shell, so
`$var`, `$?` and `$(…)` inside `bash -lc '…'` get expanded (to empty) before bash runs.
For anything with `$`, feed the script on stdin:

```bash
wsl -- bash -s <<'EOF'
echo "$HOME"
EOF
```

## Outputs and flashing

- `~/zmk-toucan-bt60/firmware/*.uf2`. From Windows:
  `\\wsl.localhost\Ubuntu\home\mbarrben\zmk-toucan-bt60\firmware\`
- Double-tap reset on the XIAO to mount its UF2 drive, then copy the `.uf2` onto it. The Tofu65 needs UF2 family `0x59952840`, which `klink//zmk` builds already emit.
- Keymap-only changes need only the dongle reflashed: `toucan_dongle_<layout>.uf2` for the
  status screen in use. The keymap lives on the split central.

## Checking RAM / flash

The link step prints a `Memory region  Used Size` table per target. The dongle's `RAM:`
line is the one that matters (radii is the highest). Afterwards, read the map:

```bash
wsl -- bash -s <<'EOF'
m=~/.cache/zmk-ws-main/build/dongle_radii/zephyr/zmk.map
grep -E "_image_ram_end = \.|_flash_used = " "$m"
grep -A1 -E "^ \.bss\.zmk_keymap$" "$m"
EOF
```

RAM used = `_image_ram_end − 0x20000000`, out of 262,144 B. `.bss.zmk_keymap` is
layers × 109 positions × 16 B (`0x28e0` with 6 layers; 107 positions on the BT60 branch).

Reference at `ee7727a` (`toucan2_zmk4_tofu65`, 6 layers):

|Dongle layout|RAM used|FLASH used|
|---|---|---|
|classic|227,834 B (86.9 %)|577,712 B|
|radii|236,410 B (90.2 %)|574,992 B|
|field|228,858 B (87.3 %)|514,320 B|
|operator|231,290 B (88.2 %)|478,360 B|
